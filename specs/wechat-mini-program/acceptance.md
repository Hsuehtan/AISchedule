# 微信小程序适配验收矩阵

- 对应规格：[WX-MVP-001](./spec.md)
- 状态：验收定义草案；以下项目全部未执行，表格不是通过报告。
- 目标路线：企业主体小程序壳 + 完整业务 H5，保留用户名密码登录。

## 证据规范

验收报告记录 commit、壳/H5/API 版本、环境、验证时间、设备/OS/微信/基础库版本、用例结果和缺陷编号。设备截图仅使用合成数据，不包含密码、Session、Key 或完整私人对话。自动化输出与真机记录分开，不能用 Chrome 截图替代微信证据。

状态使用 PASS / FAIL / BLOCKED / NOT_RUN。外部认证或域名未就绪时，相关用例写 BLOCKED 并说明依赖；不把开发工具跳过校验的成功记为合法环境 PASS。真实 AI 调用事先获准，使用合成输入；故障和并发验证优先使用 Stub。

## A. 工程与加载

| ID  | 验证方式          | 操作与预期                                                                                                           |
| --- | ----------------- | -------------------------------------------------------------------------------------------------------------------- |
| A01 | 自动化            | 新壳在 Node 24/pnpm 11 锁定依赖下可构建，输出与 H5 隔离；根级构建不会错误覆盖 H5                                     |
| A02 | Vitest + 配置检查 | trial/release 缺少 AppID/Origin、使用 touristappid、HTTP/IP/localhost/非白名单主机时构建失败；开发配置不能混入发布包 |
| A03 | Vitest + 工具     | 启动参数注入外域 url/redirect、伪造 token、相似域名或 URL userinfo，均不能改变固定 WebView 入口                      |
| A04 | 工具 + 真机       | 使用实际企业 AppID 和合法业务域名，打开域名校验；开发版/体验版可进入 H5，包体和平台检查无阻断项                      |
| A05 | 浏览器 + 真机     | 网页加载失败显示明确反馈，可返回/重进；收到 WebView error 后显示原生重试页；H5 资源加载失败有刷新入口                |
| A06 | 真机              | 每台 iOS/Android 稳定 Wi-Fi 下 5 次冷启动，无白屏，5 秒内出现可操作登录/任务页；记录每次时间，未达标记 FAIL          |

## 阶段判定

- 工程适配完成：A01–A03、相关单元/集成与 H5 回归通过；真机或资料项未执行必须显式列出。
- 体验版验收通过：A–D 与 E02–E05 均通过；A04 使用合法账号和域名。E01 中未影响体验权限的剩余正式提审材料可继续准备，但必须列明，不能称为“可提审”。
- 可提审：上述验收全部通过，E01 完成，用户批准提交。上传审核不等于发布。
- 已发布：平台审核通过，用户批准正式发布，并记录实际版本和回滚入口。

此处是产品成功条件与验证定义，不是实施任务拆分。计划、任务和代码须在规格审阅后按技能门禁继续。
