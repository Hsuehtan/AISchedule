# ADR-008：Phase 2 范围收敛与 H1 后续修正

- 状态：已批准
- 日期：2026-07-14
- 覆盖：ADR-003 的 P0 昵称编辑范围、ADR-006 的 P0 提醒交付范围，以及 PRD v1.3 的手工撤销范围

## 背景

H1 已证明 Electric Ink 视觉方向和页面层级可行，但当时使用 Fixture 与 `?screen=` 状态串联，不能代表真实认证、筛选、编辑和浏览器返回逻辑。进入 T10-T17 前，产品进一步收敛优先级、昵称、提醒和撤销范围，避免为未验证体验提前建设后台调度或通用逆向操作框架。

## 决策

1. H1 视觉方向通过；正式跳转不冻结，T10-T17 必须改为真实 Session、`projectId`、`taskId` 和服务端状态驱动。H1 Fixture Gallery 与正式入口隔离。
2. 任务优先级只有 HIGH、MEDIUM、LOW，新任务默认 MEDIUM；右侧指示点固定为红、黄、绿。左侧标签表示任务所属项目，并与项目 Chip 使用同一名称和项目身份色。项目色不表达优先级。
3. 昵称字段和默认值“用户”继续保留，但 P0 不提供修改入口或 `PATCH /users/me/profile`。手机号仍可在注册时选填，并仅作为未验证 Contact 保存。
4. `scheduledAt`、`deadlineAt`、`reminderAt` 继续支持保存、编辑、清空和展示。站内到期提示、提醒调度、已读状态和 Push 延期，不属于 T17 或当前 P0 发布条件。
5. 只有软删除创建服务端 UndoOperation，有效期固定 3 秒并以服务端 `expiresAt` 为准。创建、完成和恢复不生成 UndoOperation；完成后的长期恢复通过已完成区完成。
6. Task、Project 和 Undo 等认证后的业务写接口要求 `Idempotency-Key`。注册、登录和退出是明确例外：注册依赖唯一身份与单事务，登录每次创建新 Session，退出天然幂等。
7. 新用户初始 grant 的最小原子链路前移到 T10，注册事务同时创建用户、唯一 grant 流水并更新余额。每日补足、完整积分网关和管理员调账仍由 T18 交付。
8. T17 完成后必须生成 H2 审查包并暂停；未经人类通过不得进入 T18。

## 后果

- Phase 2 不建设昵称编辑页、提醒 Worker 或通用手工 Undo 框架。
- 原 H1“完成后撤销”仅作为历史视觉状态，不是 Phase 2 业务真源；正式客户端把 3 秒 Toast 用于删除撤销，完成任务可从已完成区恢复。
- 未来恢复昵称编辑或提醒交付时必须新建后续 ADR，并补充权限、调度、测试和迁移方案。
