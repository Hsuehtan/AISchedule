# ADR-010：Agent 可观测性数据边界

- 状态：Accepted
- 日期：2026-07-17
- 关联：[`ADR-009`](ADR-009-python-agent-service-boundary.md)

## 背景

Python Agent 服务需要通过模型调用成功率、耗时、Token 消耗、结构修复率和工具步骤失败率持续改进算法。但它又必须与用户、积分、任务、项目、会话、提案和执行状态保持绝对隔离，不能因为“需要日志”逐步演变成第二个业务事实源。

可观测数据与业务数据有不同目的：前者用于回答“算法为什么慢、贵或失败”，允许在故障时丢失；后者决定用户看到什么、是否扣分、是否重试和是否执行写操作，必须具备事务与审计语义。两者不得混用。

## 决策

Python Agent 在任何阶段都不得读取或写入业务 PostgreSQL，也不得拥有业务数据库凭证或网络路径。它保持**业务状态无状态**，只通过 NestJS 传入的有界请求执行当前推理。

允许 Python 产生算法遥测，并将其通过结构化日志或 OTLP 写入独立的 Collector/可观测性后端。该后端属于平台可观测性数据面，不属于业务数据库，也不进入 Prisma Schema。P0 在 T19 只建立遥测发射和传播能力；持久化后端、保留期和仪表盘在 T26 交付，不为此新增 Agent 执行状态数据库。

### 数据面分工

| 数据面          | 写入方                               | 用途                                         | 正确性要求                     |
| --------------- | ------------------------------------ | -------------------------------------------- | ------------------------------ |
| 业务 PostgreSQL | 仅 NestJS/Prisma                     | Run、会话、结果、提案、积分、幂等和恢复      | 产品事实源，事务一致           |
| 算法遥测        | Python/NestJS 发射，Collector 持久化 | 模型/工具步骤性能、Token、错误、链路         | 旁路、可丢失、不可参与业务判断 |
| 产品评测事件    | 仅 NestJS                            | 用户修正、确认、执行结果与算法版本的业务审计 | 业务数据，按 userId 隔离       |

`requestId` 和 `traceId` 是跨数据面唯一允许的关联键。它们可以出现在受控日志/Trace 字段中，但不得成为 Metrics Label；算法遥测默认不包含 `userId`、真实 Task/Project ID 或 `reservationId`。

### 允许记录的白名单

- 服务、环境、版本、`requestId`、`traceId` 和稳定事件名。
- capability、结果类型，以及实际使用的 Provider、模型、Prompt、Provider Schema、内部契约和工具版本。
- Provider/步骤状态、稳定错误分类、调用次数、结构修复次数、限流与重试分类，以及经过 Hash/脱敏的 Provider request ID。
- 输入/输出 Token 数、总 Token 数、耗时、首 Token 耗时和估算的 Provider 成本。
- 算法内纯计算工具的名称、版本、状态和耗时；不得记录其参数或结果正文。

默认禁止记录：

- 密码、Session、手机号、积分余额、`reservationId`、管理员身份或任何 Secret。
- 完整私人任务/项目/对话、原始 Prompt、完整模型响应、工具参数/结果正文和 Provider 原始正文。
- Chain of Thought、隐藏推理、`candidateRef`、跨用户数据、业务数据库 ID，以及可由高基数字段推断用户身份的 Metrics Label。

如果算法迭代确实需要输入/输出样本，必须另立评测数据方案，经人工审查后采用显式抽样、字段脱敏、访问控制、保留期和删除机制；普通生产日志不得顺便承担训练集或评测集职责。

### 故障与恢复语义

- 遥测发送采用有界、非阻塞、失败开放策略；Collector 或存储不可用不能让一次本可成功的 Agent 请求失败，也不能改变用户积分。
- 遥测不能作为 Run、幂等、计费、结果开放、迟到响应、重试或故障恢复的判断依据。
- Python 和 NestJS 线上业务代码都不得从遥测后端读回历史来接受、拒绝、复用或恢复 execute。
- 业务恢复只读取 NestJS/PostgreSQL/pg-boss 中的事务状态；Provider 若提供幂等能力，可由 Python 在单次执行协议内使用，但其结果仍须由 NestJS 校验和持久化。
- 遥测失败只产生有界的丢弃计数/告警，不允许无限本地缓冲、阻塞请求或把原始正文降级写入磁盘。
- 此前设想的“Python 持久化幂等 Run API”不再作为含糊超时的恢复方向。改变这一绝对边界必须新立 ADR 并经过人工门禁。

### 保留与访问

- T26 默认目标：明细日志/Trace 保留 14 天，聚合 Metrics 保留 90 天；均可通过部署配置缩短，不得无限期保留。
- 可观测性后端使用与业务数据库分离的凭证、网络策略、备份策略和访问角色；Python 最多拥有只写遥测能力。
- 导出、检索和删除操作需要审计；生产真实样本默认关闭。
- 若引入付费可观测服务或新增敏感数据类别，必须在 H4 前取得人工批准。

## 结果

### 正面

- Python 可以用足够的性能和成本信号迭代 Agent，而不获得业务数据权限。
- 积分、幂等和恢复仍只有一个事实源，遥测丢失不会造成错扣、重复调用或重复写入。
- 未来更换可观测性厂商不影响内部 Agent 契约和业务数据模型。

### 代价

- 需要维护事件白名单、Trace 传播、保留策略和遥测丢失告警。
- 默认不保存原始输入/输出会限制问题复盘深度；需要样本时必须走独立评测数据审批。

## 验证要求

- Python 运行环境不存在业务数据库凭证，网络策略拒绝访问 PostgreSQL。
- 遥测 Sink 断开、超时或拒绝写入时，契约有效的结果仍可由 NestJS 持久化和结算一次。
- 日志 Schema 快照证明敏感字段、正文和 Chain of Thought 不在输出中；Metrics Label 集合固定且有界。
- 同一 `requestId/traceId` 可关联 NestJS 与 Python 链路，但遥测删除后业务状态、积分对账和故障恢复结果不变。
