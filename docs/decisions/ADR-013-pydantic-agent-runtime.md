# ADR-013：受限 Pydantic AI Runtime 与统一 Flash

- 状态：用户批准并已实施；2026-10-27 本专项验收通过，T24/H3/H4 门禁不变，见[最终报告](../quality/2026-10-27-pydantic-agent-final-acceptance.md)
- 日期：2026-10-26
- 继承：ADR-009、ADR-011、ADR-012 的业务边界、上下文所有权和日志限制

## 决策

Python 推理使用 `pydantic-ai-slim[openai]` 的 Agent、结构化 ToolOutput 和只读工具。所有请求均使用 `deepseek-v4-flash`，显式关闭 Thinking，取消按任务选择模型。v2 在一次 execute 内可读取任务、项目和较早历史；v1 经兼容适配器使用同一 Runtime，不开放额外上下文工具。NestJS 仍独占 Run、积分、鉴权、候选映射、提案和确认后的业务写入。

每个产品请求只派发一次 execute。单次 execute 最多四次模型请求，其中最多三次常规推理、一次结构修复；最多六次串行只读工具调用。模型输出上限 4096 tokens，SDK/HTTP 自动重试关闭。上下文和模型共享既有截止时间，预留两秒返回。预算耗尽返回稳定失败，不伪造成功结果。内部模型/工具调用不额外扣积分。

初始读取来源与最近 20 条历史（正文 12 KiB）。任务、项目、历史的单页默认分别为 50、30、20 条；累计分别为 200、60、60 条；模型业务上下文总量 64 KiB。这些是 Python 策略，TS 仅保留技术性单页保护。候选只以本 Run 临时引用传输；旧草稿不构成新的写入授权。

内部 v2 契约增补安全任务字段和多字段整理、修改项目的表达；严格客户端默认仍获得旧投影。五类结果与七类 Action 的产品形态不变。所有写入均须用户确认，确认时 NestJS 复验归属、状态、版本和业务数量限制。

离线合成评测和真实 Flash 评测仅保存 Case ID、版本、得分、失败分类、耗时及调用次数。Python 生产日志仍遵守 ADR-011，不启用持久化 Trace 或远程观测。微信、飞书与 MCP 连接器留待后续决策；本轮不进入 T25–T27，也不改变 H3/H4 门禁。

2026-10-27 复验补强：Prompt v3 对必要信息缺失使用澄清卡，当前项目仅作为范围而非修改授权。Python 根据用户 IANA 时区计算今天、明天、下一自然周与带正确未来 DST 偏移的日历参照；时间输出使用 UTC。评测采用独立冻结时钟，保留 ZoneInfo 身份，不影响生产时钟或 execute 截止时间。正式 120 Case 与额外三个时区的 15 Case 分开计分；旧契约不支持的多字段整理和修改项目共 14 Case 不纳入新旧同能力比较。

Runtime v4 复验时在实际模型调用边界追加独立防护：第三次常规请求与修复请求不发送读取工具定义；全 Run 的 Schema/引用修复共享一次预算，不因切换输出类型重置；非法工具参数不进入额外模型重试。框架 UsageLimits 与 SDK 重试配置仍保留，成功结果的 `repairAttempts` 同时计入 Schema 修复。调用边界状态只存在于本次 execute 内，不持久化、不新增日志依赖。

失败边界收口为 Runtime v5：空响应、空白文本与仅 Thinking 的非可用响应直接终止，不进入框架默认重试；429/5xx 和上下文失败同样不增加模型请求。最终验收使用 v5 完整三轮，限流和环境失败不能以总体通过率达标替代证据完整性。

最终验收 120 Case × 3 轮为 356/360（98.89%），通过已批准的逐轮、分类、时延和调用预算门槛；3 次不必要澄清、1 次预算保护终止保留为剩余限制。当前正式页面 20 阶段、12 视口检查、19 Run 与 19 笔积分结算核对，以及用户对两个回复/计划样本的人工审阅均通过。工具尝试与上下文读取分别计数，不将缓存命中或重复工具调用漏计。
