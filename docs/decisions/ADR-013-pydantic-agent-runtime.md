# ADR-013：受限 Pydantic AI Runtime 与统一 Flash

- 状态：用户批准，T24 专项实施中；验收以本专项报告为准
- 日期：2026-10-26
- 继承：ADR-009、ADR-011、ADR-012 的业务边界、上下文所有权和日志限制

## 决策

Python 推理使用 `pydantic-ai-slim[openai]` 的 Agent、结构化 ToolOutput 和只读工具。所有请求均使用 `deepseek-v4-flash`，显式关闭 Thinking，取消按任务选择模型。v2 在一次 execute 内可读取任务、项目和较早历史；v1 经兼容适配器使用同一 Runtime，不开放额外上下文工具。NestJS 仍独占 Run、积分、鉴权、候选映射、提案和确认后的业务写入。

每个产品请求只派发一次 execute。单次 execute 最多四次模型请求，其中最多三次常规推理、一次结构修复；最多六次串行只读工具调用。模型输出上限 4096 tokens，SDK/HTTP 自动重试关闭。上下文和模型共享既有截止时间，预留两秒返回。预算耗尽返回稳定失败，不伪造成功结果。内部模型/工具调用不额外扣积分。

初始读取来源与最近 20 条历史（正文 12 KiB）。任务、项目、历史的单页默认分别为 50、30、20 条；累计分别为 200、60、60 条；模型业务上下文总量 64 KiB。这些是 Python 策略，TS 仅保留技术性单页保护。候选只以本 Run 临时引用传输；旧草稿不构成新的写入授权。

内部 v2 契约增补安全任务字段和多字段整理、修改项目的表达；严格客户端默认仍获得旧投影。五类结果与七类 Action 的产品形态不变。所有写入均须用户确认，确认时 NestJS 复验归属、状态、版本和业务数量限制。

离线合成评测和真实 Flash 评测仅保存 Case ID、版本、得分、失败分类、耗时及调用次数。Python 生产日志仍遵守 ADR-011，不启用持久化 Trace 或远程观测。微信、飞书与 MCP 连接器留待后续决策；本轮不进入 T25–T27，也不改变 H3/H4 门禁。
