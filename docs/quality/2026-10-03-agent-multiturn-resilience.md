# Agent 多轮对话与异常恢复专项复验

日期：2026-10-03。用户反馈 Action 未正确执行、计划浮层及处理中流程卡住，授权扩展功能测试和修复。范围仍为 T24，不进入 T25–T27。

## 实际复现与修复

| 编号 | 触发条件及修复前现象                                                                             | 修复                                                                                                                             |
| ---- | ------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------- |
| R01  | 计划确认项目名称冲突，或确认已经落库但网络响应丢失；浮层仍显示可编辑、可创建，点击创建无实际动作 | 传递真实 Proposal 状态；失败、执行中、已执行、取消、过期、替代状态不显示无效创建按钮；响应丢失后读取真实状态，重复确认不重复写入 |
| R02  | 已失败计划点击重新生成，被服务端拒绝                                                             | 允许版本匹配的 FAILED 计划作为重生成来源；成功后替代旧提案，保留原执行记录；新结果失败时保留旧状态                               |
| R03  | 正在编辑计划项，尚未保存就能点击“创建 N 项”，实际执行旧内容                                      | 编辑期间禁止直接确认和重新生成，保存成功后再开放                                                                                 |
| R04  | 计划项保存请求失败，已输入标题被旧数据覆盖                                                       | 编辑器以计划项 ID 区分生命周期，父组件刷新不重置本地输入；失败保留输入并允许重试                                                 |
| R05  | 生成计划请求已受理但响应尚未返回时关闭对话，稍后浮层自行重开                                     | 检查发起请求时的面板是否仍活动；关闭后只刷新业务状态，不强制打开面板                                                             |
| R06  | 处理中关闭对话，后台完成后首页仍一直显示“查看进度”                                               | 页面可见且 Inbox 为 PROCESSING 时每 2 秒刷新，完成后更新到结果入口                                                               |
| R07  | 重生成请求已受理、尚未完成时关闭旧计划浮层，dismiss 增加来源版本，新 Run 最终 RELEASED           | 进行中的确认、编辑、重生成关闭只离开界面，不额外更改来源版本，后台操作继续                                                       |

此外，移除按请求 ID 永久屏蔽重复错误/终态处理的客户端集合；同一请求恢复打开后仍可处理结果和错误。确认直到业务刷新完成都保持交互锁；历史提案随结果刷新，避免旧状态缓存；整理建议移除失败不会留下未处理的 Promise。

这些修复不修改积分规则、Action 原子事务、单次 execute dispatch 或公开 API Schema，不增加模型自动重派。

## 覆盖矩阵

新增 `tests/e2e/agent-resilience.spec.ts`，使用正式 H5、真实 NestJS/隔离 PostgreSQL 和确定性私有 Agent Stub：

1. 项目名称冲突 → 失败计划只读 → 重生成 → 原子创建。
2. 生成计划受理期间关闭对话 → 不自动重开 → Inbox 恢复。
3. 同一 Run 连续两次查询失败 → 仍有明确失败出口。
4. 确认已落库但响应丢失 → 展示已执行 → 重复确认不重复创建。
5. 编辑未保存禁止确认 → 保存后创建修改后的内容。
6. 同一会话连续创建、修改、完成、恢复、删除任务、创建项目任务；历史卡保持已执行，双击不重复写入。
7. Action 目标版本变化 → 不写入 → 新一轮重新生成并确认成功。
8. 处理中关闭 → 首页自动更新 → 恢复后可继续对话。
9. 重生成双击只派发一次、旧稿被替代且不可确认；再次重生成期间关闭，Run 仍成功且不弹回浮层。
10. 编辑保存失败保留输入，重试后按编辑内容执行。

既有正式 Agent 5 个 E2E 继续覆盖文字输入、多轮澄清、确定性答案、自由文本答案冲突、Action 追问取消及失败重试、整理移除单项、删除三秒撤销、计划编辑/关闭恢复、移动视口和无障碍。

客户端新增 6 个计划终态展示断言。数据库集成增加 FAILED 来源的重生成分支，复验新推理失败保留旧稿、成功才替代；既有 Agent 测试继续覆盖归属、版本、稳定候选引用、事务回滚、结算恢复与旧 Run 兼容。

## 真实模型验证

扩展现有 `pnpm smoke:deepseek`，仍仅使用隔离数据库和合成用户/任务，从根目录 `.env` 向测试进程选择性注入凭证；仅 Python 子进程持有 Provider 凭证，不输出密钥、Prompt 或模型正文。

- 原普通回复/计划生成 Smoke：通过，Flash/Pro、结果持久化、1 点/2 点结算；本轮核心耗时 24,262 ms。
- 新增同一会话七类 Action Smoke：通过，CREATE_TASK / UPDATE_TASK / COMPLETE_TASK / RESTORE_TASK / DELETE_TASK / CREATE_PROJECT_TASKS / ORGANIZE_TASKS；每项均实际确认、验证任务结果、再次确认检验幂等，并核对成功 debit 与 Run 数量。核心耗时 16,898 ms。
- 合计 2/2，完整执行 46.34 秒。

首轮扩展测试把明确指令后的响应限定为立即 ACTION_PROPOSAL，模型在 CREATE_PROJECT_TASKS 返回 CLARIFICATION。测试随后补齐合法的自由文本澄清回答分支，最多回答一次，不自动重派原 Run，也未为了测试修改 Prompt。模型选择澄清还是直接生成具有不确定性；单次 Smoke 通过不表示所有自然语言表达均正确。
