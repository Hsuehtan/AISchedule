# 移动端 UI 视觉审查

日期：2026-09-29。范围：本次截图集中全部 41 张 390 x 844、320 x 844 图片；480px 宽屏不在本次评审范围。

## 结论

Electric Ink 的深色、白色与亮青色已经建立了清楚的产品识别，任务首页的基本结构也容易理解。建议继续沿用这个方向，优先统一文字尺度、操作层级、浮层布局和状态表达。

当前最影响完成度的三项是：计划与 Action 确认区字号异常放大；320px 下多处文字随页面整体缩小；编辑待办的底部操作出现两行不对称排布。它们应先于阴影、圆角等装饰细节处理。

本文是视觉审查建议，不改变已批准的 PRD、功能范围或 T24 门禁。尺寸属于建议起点，后续设计定稿和实施时需对照当前 Figma Production V3；本轮没有执行 Figma 逐像素比对。

## 证据说明

- 截图来自正式 H5 代码、隔离数据库和合成账号。Agent 分支使用确定性替身；额度不足页使用模拟响应。
- 逐张检查发现上一轮部分浮层截在进入/退出动画期间。本轮为截图辅助函数增加 450ms 稳定等待并重新采集，项目管理、新建、改名、归档确认和任务编辑现在对应正确画面。
- 重新采集的六组用例均完成并输出通过；测试进程随后停留在收尾阶段，人工中断后退出码为 130。此结果用于截图有效性说明，不作为新的完整工程门禁通过结论。
- 以下所述字号大小的视觉比较来自截图；推荐尺寸是设计建议，不把截图估算值写成精确实测值。

## 优先修正

### V01：计划与 Action 确认区的文字层级失衡

证据：[计划草稿](screenshots/visual-sweep-2026-09-29/30-agent-plan-draft-390x844.png)、[编辑后的计划](screenshots/visual-sweep-2026-09-29/32-agent-plan-edited-390x844.png)、[操作确认](screenshots/visual-sweep-2026-09-29/38-agent-action-confirm-390x844.png)。

项目标题、任务标题、序号和“待确认”都以接近展示标题的尺度呈现，普通任务名被挤成两行甚至分散到很窄的列里。只有两条任务也占据了大部分浮层，视觉重心混乱。

建议：浮层标题 18px/26px；摘要标题 16px/24px；任务标题 15px/22px；序号 12px；优先级与状态 11-12px。任务文本占据主要宽度，序号和编辑控件使用固定轨道；状态作为次级标签。短标题一行，长标题允许两行。编辑入口用清晰的编辑图标，保持至少 44px 热区。

验收观察点：同一视口能连续扫描多条任务；“待确认”不再与任务标题争夺注意力；长任务名不会被侧边状态挤成逐字换行。

### V02：320px 适配正在缩小阅读尺度

证据：[390px 首页](screenshots/visual-sweep-2026-09-29/12-all-todos-mixed-390x844.png)与[320px 首页](screenshots/visual-sweep-2026-09-29/13-all-todos-mixed-320x844.png)；[390px 表单](screenshots/visual-sweep-2026-09-29/17-task-create-filled-390x844.png)与[320px 表单](screenshots/visual-sweep-2026-09-29/18-task-create-filled-320x844.png)；[390px 对话](screenshots/visual-sweep-2026-09-29/28-agent-reply-390x844.png)与[320px 对话](screenshots/visual-sweep-2026-09-29/29-agent-reply-320x844.png)。

窄屏里的项目标签、表单标签、字段值和部分对话正文明显更小。对话浮层在相同 844px 屏高下也变矮，额外露出了大片背景，压缩了真正有用的对话空间。

建议：320px 和 390px 使用相同的主要文字尺度；通过减少左右间距、换行和纵向滚动适配。正文/字段值建议 14-15px，辅助信息 12px；页面标题可统一 24-26px。对话浮层按可用屏高确定上限，不随屏宽等比缩短；主按钮和图标按钮保持至少 44px 热区。

验收观察点：并排查看两种宽度时，文字具有接近的实际阅读大小；窄屏增加换行而非整体缩成微型界面。

### V03：底部按钮排布与主次关系不稳定

证据：[编辑待办](screenshots/visual-sweep-2026-09-29/20-task-edit-390x844.png)、[登录](screenshots/visual-sweep-2026-09-29/01-login-default-390x844.png)、[注册](screenshots/visual-sweep-2026-09-29/03-register-default-390x844.png)、[计划草稿](screenshots/visual-sweep-2026-09-29/30-agent-plan-draft-390x844.png)。

编辑待办的“删除、取消”占第一行，“保存”单独落在下一行左半侧；主操作位置不稳定，删除反而拥有很强的第一视觉。登录/注册的主次按钮上下贴合，计划草稿的主按钮与上一排按钮也缺少间距。

建议：编辑表单底部固定“取消 + 保存”，保存为唯一亮青色主操作；删除保留为独立的低强调危险操作，与保存拉开距离。确需三项同区时，应采用明确且对称的布局，不允许 2+1 意外换行。所有相邻按钮保持 8-12px 间距。

验收观察点：每个浮层第一眼即可找到主操作；按钮在 320px 与 390px 下无意外换行、粘连或孤立半宽状态。

### V04：浮层需要按内容类型确定高度和操作区

证据：[新建项目](screenshots/visual-sweep-2026-09-29/07-project-create-empty-390x844.png)、[项目改名](screenshots/visual-sweep-2026-09-29/10-project-rename-390x844.png)、[归档确认](screenshots/visual-sweep-2026-09-29/11-project-archive-confirm-390x844.png)、[计划项编辑](screenshots/visual-sweep-2026-09-29/31-agent-plan-item-edit-390x844.png)、[语音不可用](screenshots/visual-sweep-2026-09-29/42-voice-deferred-390x844.png)。

短内容浮层的按钮下面有大块无用途空白；长表单里，计划摘要仍占很大面积，保存操作却离开了首屏。相同底部浮层组件呈现出不同的垂直节奏。

建议建立三种规格：短提示按内容自适应；编辑表单采用受屏高约束的滚动内容区和固定底部操作区；连续对话采用稳定的大浮层和固定输入区。进入计划项编辑时，把大摘要压缩成一行上下文。长内容只保留一个主要滚动区域，底部留安全区。

验收观察点：短提示没有无意义的大块底部空白；长表单可完整滚动，保存/取消始终容易到达；软键盘出现后另做实机检查，本轮静态截图不能证明键盘状态通过。

## 进一步优化

### V05：把任务重新放在首页视觉中心

证据：[待办首页](screenshots/visual-sweep-2026-09-29/12-all-todos-mixed-390x844.png)、[项目筛选](screenshots/visual-sweep-2026-09-29/15-project-filter-390x844.png)、[Smart Inbox 折叠态](screenshots/visual-sweep-2026-09-29/41-smart-inbox-collapsed-390x844.png)。

顶部深色 Smart Inbox、底部深色输入栏以及亮青色光晕都很醒目，任务列表的视觉权重相对较弱。普通状态下第一条任务约从屏幕上部三分之一之后开始。

建议保留两处 AI 入口，但把无待确认事项时的 Inbox 压缩得更紧凑，减少留白与发光；有待确认操作时再提高强调程度。底部输入栏保留一个清晰的青色动作点，减轻整条栏的阴影。普通任务卡使用细边框或轻阴影，不叠加强烈的两种效果。

默认是否折叠属于交互决策，可另行讨论；单纯降低高度与装饰强度已经能改善首页层级。

### V06：任务行的空间应优先给任务名称

证据：[长标题任务](screenshots/visual-sweep-2026-09-29/12-all-todos-mixed-390x844.png)、[窄屏任务](screenshots/visual-sweep-2026-09-29/13-all-todos-mixed-320x844.png)、[已完成项](screenshots/visual-sweep-2026-09-29/22-done-expanded-390x844.png)。

任务名很快被省略，左侧“待定”和下方“无截止时间 · 无提醒”却持续占位。完成项仍保留鲜艳的优先级点和大块青色完成圆点，与未完成任务竞争。

建议：为任务标题保留 1-2 行；时间列设稳定宽度，正文弹性扩展；缺省信息降为更弱的占位表达。完成项保留可读正文，降低元信息和彩色装饰的强度，并使用清晰的勾选符号。项目身份色与优先级色的既定含义保持不变。

隐藏缺省元信息会改变展示规则，需在后续设计方案中明确；不应把有值的时间或提醒藏掉。

### V07：表单应更容易扫描，也更像可操作的控件

证据：[新建待办](screenshots/visual-sweep-2026-09-29/16-task-create-empty-390x844.png)、[已填表单](screenshots/visual-sweep-2026-09-29/17-task-create-filled-390x844.png)、[日期时间选择](screenshots/visual-sweep-2026-09-29/19-task-datetime-picker-390x844.png)。

多个浅蓝输入框从上到下权重相同，标签与字段值都偏小。所属项目、优先级、时间字段的外观与普通文本输入接近，选择型控件缺少方向提示。日期滚轮的绿色“确定”和其余页面的亮青色动作体系脱节。

建议：用间距区分“基本信息”和“时间安排”，标签 12px，字段值 14px；选择项增加统一的下拉/进入图标，时间项使用日历图标。高/中/低优先级可以采用紧凑分段控件，或保留选择器并强化当前值。滚轮保持现有五列逻辑，统一确认颜色、标题和分隔线。

### V08：统一图标、关闭方式和控件轮廓

证据：[底部输入栏](screenshots/visual-sweep-2026-09-29/12-all-todos-mixed-390x844.png)、[项目浮层关闭](screenshots/visual-sweep-2026-09-29/09-project-manager-populated-390x844.png)、[对话关闭](screenshots/visual-sweep-2026-09-29/34-agent-clarify-390x844.png)、[计划关闭与编辑](screenshots/visual-sweep-2026-09-29/30-agent-plan-draft-390x844.png)。

当前关闭入口有裸叉、圆形描边叉和方框叉；计划编辑显示为很小的“编”；语音入口像同心圆，键盘图标又过小。它们让各浮层看起来像来自不同组件系统。

建议统一为同一图标库的 18-22px 图标、同一线宽；关闭按钮采用统一视觉规格并保留 44px 热区；语音用麦克风，文字输入用键盘，单项编辑用铅笔。圆角按角色分级：标签/胶囊按钮一类，输入与列表一类，浮层一类，同一角色不混用。

### V09：文字对比度与禁用态需要独立规范

证据：[归档确认](screenshots/visual-sweep-2026-09-29/11-project-archive-confirm-390x844.png)、[删除按钮](screenshots/visual-sweep-2026-09-29/20-task-edit-390x844.png)、[空输入发送按钮](screenshots/visual-sweep-2026-09-29/24-agent-text-empty-390x844.png)、[对话禁用发送](screenshots/visual-sweep-2026-09-29/28-agent-reply-390x844.png)。

同样是不可发送，文字输入浮层仍使用高饱和青底与白字，对话页则使用灰底，状态表达不一致。粉色危险按钮的白字也偏弱。

基于当前样式定义计算，白色与 `#FF5F8F` 的对比度约为 2.88:1，白色与 `#00D8FF` 约为 1.71:1；深色 `#101420` 与亮青色约为 10.73:1。这些计算来自样式色值，不是屏幕截图取样。

建议：亮青色主按钮统一用深色文字；禁用态统一为低饱和底色、清楚的次级文字、无光晕。危险操作采用满足文字对比要求的深红文字/浅红底或更深的红色按钮；项目标签可以保留身份色点、使用深色文字。普通可用状态文字以至少 4.5:1 为验收目标；禁用组件不受该最低对比度条款约束，但仍应一眼能辨认。参见 [W3C Contrast Minimum](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)。

### V10：空状态与不可用状态可以更简洁

证据：[空首页](screenshots/visual-sweep-2026-09-29/05-tasks-empty-390x844.png)、[待确认计划时的空首页](screenshots/visual-sweep-2026-09-29/33-smart-inbox-pending-plan-390x844.png)、[语音不可用](screenshots/visual-sweep-2026-09-29/42-voice-deferred-390x844.png)、[额度不足](screenshots/visual-sweep-2026-09-29/43-agent-quota-simulated-390x844.png)。

空首页同时出现顶部新增、Inbox 创建、空态创建和底部输入，空态本身又装在一张大白卡里。“已完成 0 项”继续占用整条青色区域。语音和额度提示则把同一句说明在标题下与蓝色框里重复了两次。

建议：空态使用更轻的无边框布局，保留一个明确主操作；“已完成 0 项”降低为轻量信息或在零项时隐藏。未创建过任务与全部完成可以用不同标题，避免刚注册就产生已经清空的错觉。不可用提示保留“原因 + 可继续做什么 + 一个动作”，删除重复说明框。

零项隐藏、空态文案区分属于展示规则建议，需要在设计定稿中确认，不在本轮直接变更。

### V11：对话内容可减少装饰并强化已选择状态

证据：[普通回复](screenshots/visual-sweep-2026-09-29/28-agent-reply-390x844.png)、[澄清](screenshots/visual-sweep-2026-09-29/34-agent-clarify-390x844.png)、[选择后](screenshots/visual-sweep-2026-09-29/36-agent-clarify-answered-390x844.png)、[候选列表](screenshots/visual-sweep-2026-09-29/37-agent-candidates-390x844.png)。

现有左右对齐关系清楚，但浅底对话区、白色消息卡、青色侧线、小 Agent 标签、内层选项边框同时出现，装饰层级偏多。选择“生活”后，旧选项的视觉仍相似，用户需要读后续消息才知道哪个被选中。

建议：保留一种主要角色区分手段，简化重复边框/标签；问题和正文使用稳定的 14px 阅读尺度。选中项用轻青底和勾选标记，历史选项呈现明确的只读状态。保留当前固定底部输入区；对话较少时的留白可以存在，不需要用额外卡片填满。

### V12：界面文案与低频操作应减少工程感

证据：[登录](screenshots/visual-sweep-2026-09-29/01-login-default-390x844.png)、[注册](screenshots/visual-sweep-2026-09-29/03-register-default-390x844.png)、[任务编辑](screenshots/visual-sweep-2026-09-29/20-task-edit-390x844.png)、[项目管理](screenshots/visual-sweep-2026-09-29/09-project-manager-populated-390x844.png)、[归档确认](screenshots/visual-sweep-2026-09-29/11-project-archive-confirm-390x844.png)。

“只做真正会用的链路”“修改会校验打开表单时的版本”“本阶段不支持在 C 端恢复”等表达来自实现或项目阶段语境。项目管理里“退出登录”与“完成”放在同一底部操作行，低频账号动作占据了主要操作位置；小字号的“改名/归档”也不易扫描。

建议：正常状态文案只解释用户此刻需要知道的事情；版本冲突在真正发生时提示。必须保留的限制应转成用户语言，例如“归档后暂时无法恢复，待办仍保留在全部中”。项目列表与账户区域使用清晰分隔，退出登录改为低强调独立入口；完成保持主操作。注册仍保留用户名登录、手机号选填等已批准规则。

## 建议统一的视觉尺度

以下为移动端设计提案，320px 和 390px 共用；不是对当前设计真源的自动修改。

| 元素 | 建议起点 |
| --- | --- |
| 页面标题 | 24-26px / 32-34px，600-700 字重 |
| 浮层标题 | 18px / 26px，600-700 字重 |
| 任务标题、表单值、对话正文 | 14-15px / 21-23px |
| 元信息、字段标签 | 12px / 18px |
| 按钮文字 | 14px / 20px，600 字重 |
| 可点击目标 | 至少 44px；可见图标约 18-22px |
| 页面左右留白 | 16-20px，窄屏优先减少留白而非缩小字体 |
| 控件之间 / 组内间距 | 8-12px |
| 内容组之间 | 20-24px |
| 输入框/列表轮廓 | 同一角色使用一致圆角和 1px 边框；减少重复阴影 |
| 主操作 | 亮青底 + 深色字；同一操作区一个主按钮 |
| 底部浮层 | 统一标题、关闭入口、安全区和主滚动区域；按内容类型选择高度 |

## 建议处理顺序

1. V01-V04：字号、窄屏适配、操作布局与浮层结构。先解决影响阅读和执行的明显问题。
2. V08-V09：图标、按钮状态与文字对比度。建立可复用的统一组件规格。
3. V05-V07、V10-V12：首页层级、任务行、表单、空态、对话和文案精修。

随后沿用同一组截图数据进行前后对照，并补充 320px 短屏、软键盘、较长任务/项目名和多条计划的状态，避免只优化短文本样例。

独立交互问题：上轮记录的 Smart Inbox 折叠后无法展开仍需另行修复。它不计入本次视觉建议的改善收益。
