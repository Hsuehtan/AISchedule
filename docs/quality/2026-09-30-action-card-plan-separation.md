# 对话 Action 卡与计划草稿分离复验

日期：2026-09-30。范围：正式 H5、公开提案契约、NestJS 提案持久化及确认；Agent 服务替身和隔离数据库使用合成数据。T24 仍待人工审查，未进入 T25–T27。

## 结论

- `presentation` 从关联 Run 的持久化结果类型确定。`PLAN` 进入可编辑计划草稿浮层；`ACTION_PROPOSAL` 进入原对话消息区的白底深边框 Action 卡，即使操作码为批量创建项目与任务也不改变分类。提案查询、编辑、取消、确认和旧幂等快照重放返回同一字段，未增加数据库列或 Python 协议字段。
- Action 卡使用 Mutation 快照呈现真实对象、字段前后值和界面影响；覆盖新建、整理、修改、完成、恢复、软删除及新建项目。未知项目显示“项目不可用”，不伪装成“未归属”。整理建议可逐项移除，但保留至少一项。确认成功后留在当前对话，原卡显示“已执行”；计划草稿确认后仍返回首页。
- “继续对话”仅聚焦固定底部输入；打字、关闭不取消。发送追问时先取消目标 Action，再用相同 `conversationId` 提交。取消失败会刷新卡片并停止发送；取消成功后发送失败，旧卡保持不可执行，草稿保留可重试。确认与追问使用共同提交锁；网络结果不明时读取服务端提案状态。历史卡读取失败提供对话内重试。
- 删除 Action 的三秒撤销入口在对话内部可见、可通过键盘进入，期限仍由服务端 `expiresAt` 决定。

上一轮 [V01 专项](2026-09-30-mobile-v01-revalidation.md)修正了计划与旧 Action 浮层的字号和行宽，但没有解决两种展示结构混淆。本文的截图和交互检查针对本次结构修正。
