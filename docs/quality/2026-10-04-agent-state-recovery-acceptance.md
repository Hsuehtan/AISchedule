## 修复结论

| 问题 | 修复后的业务语义 |
| --- | --- |
| 重生成期间关闭或另一标签页关闭旧计划，导致来源版本变化 | dismiss 只记录 `lastDismissedAt`，不递增 Proposal 业务版本；编辑、取消和确认仍执行版本校验并推进版本 |
| 新计划成功后，旧失败 execution 继续占据 Smart Inbox | 失败入口只依据 Proposal 当前 `FAILED` 状态；`SUPERSEDED` 等终态不再被历史 execution 复活，审计记录不删除 |
| 已过期 FAILED 计划仍可预留积分和派发，结果必然失败 | FAILED 与待确认草稿统一采用七天有效期；重生成前先持久化 `EXPIRED` 并拒绝入场，不创建 Run、预留或队列任务 |
| 入场后、结果返回前来源计划过期 | 结果接收仍复验有效期，拒绝迟到结果并释放预留；不自动重派，来源提案和历史执行保持可审计 |
| 完整 E2E 被同 IP 注册限流打断 | 普通业务用例通过 `AuthService` 在隔离库创建真实 User、Session 和新用户积分；认证专项继续走公开注册接口，正式限流未放宽 |
| 明确写操作偶尔被真实模型输出为普通回复 | Python Prompt 明确要求信息充分的写操作优先返回待确认 `ACTION_PROPOSAL`，并指定“新项目 + 任务”使用 `CREATE_PROJECT_TASKS`；歧义目标仍进入澄清或候选选择 |

未增加公开 API、数据库结构、Python 业务权限或模型自动重派。

## 覆盖范围

- Action：七类 Action 的准确目标、状态和字段；旁观任务不变；确认前无写入；重复确认不重复写入、派发或扣分。
- 计划：生成、编辑、保存失败保留输入、未保存禁止确认、FAILED 重生成、并发 dismiss、替代关系、取消和过期。
- 恢复：确认响应丢失、轮询失败、处理中关闭、刷新任务列表失败、页面恢复、迟到结果和目标版本冲突。
- 后端：单次 dispatch、积分预留/释放、结果持久化后只结算、候选引用复验及 v1/v2 存量兼容。
- 浏览器真实模型：正式 H5 中自然语言创建并确认、指代修改并确认；回复转计划、编辑、重生成、处理中关闭、Smart Inbox 恢复并确认。
